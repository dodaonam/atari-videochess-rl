### RSK-010 lossless migration branch verification — 2026-10-23

The merged `initial-idea` baseline at `16fc01a3fe731c0a0be127026cc64d049c0cf550` measured 3,919,833 bytes. It contained 139 inline history records; its `last_checkpoint` was not one of those rows and was therefore added as the 140th logical archive record. The migration preserved the original state bytes in a compressed SHA-256-verified backup, reconstructed the ordered history independently, and reduced the compact state to 65,811 bytes. Synthetic tests exercise interrupted migration, partial writes, append rollback/roll-forward, no-op checkpoints, archive corruption, and a clean clone. The versioned format does not discard history; the archive and manifest still grow with retained records. This implementation is on an unmerged feature branch, so the operational risk remains open until owner review, merge, and integration-branch recovery verification complete. Before M4 begins, merge the migration and verify preflight from a clean clone. Before the archive approaches 64 MiB, review a separately authorized durable-storage strategy; do not delete segments.
