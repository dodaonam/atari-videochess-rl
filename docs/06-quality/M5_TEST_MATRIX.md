# M5 Double DQN Verification Matrix

**Contract:** `m5-tests/2.0`, aligned to `videochess-m5-ddqn-config/2.0`. This matrix defines implementation evidence and does not itself pass acceptance criteria.

| Area | Required executable evidence |
|---|---|
| Target calculation | Drive the real target calculator with every retained disagreement fixture. Prove online argmax selects the legal UCI, target evaluates that exact UCI, and terminal/truncation arithmetic is correct. Reject candidate set mismatch, NaN/Inf, illegal, stale, duplicate and promotion identity errors. |
| Transition integrity | Reconstruct complete standard-start histories, current/next legal sets, optional opponent reply and resulting state. Test fixed agent color/reward perspective, automatic outcomes with raw legal moves, real 400-decision truncation, and reject fabricated/inconsistent flags or outcomes. |
| Model initialization | Verify real M4 checkpoint SHA, sidecar, artifact manifest, schemas and M3 provenance. Compare all intended shared tensors, prove behavior head exclusion and new Q head, independently seeded Scratch representation, paired Q-head initialization and target/online equality. Verify engine-free inference. |
| Replay and update | Capacity 16,384/eviction, deterministic insertion and sampling, seeded RNG restore, integrity journal/prefix recovery, duplicate/corrupt transition rejection, variable history/candidate collation, update cadence, warm-up 1,024, Huber loss, clip norm, finite gradients/parameters, target frozen between hard copies and sync every 500 updates. |
| Exploration | Legal epsilon-greedy actions, deterministic ties, epsilon 1.0 at decision 0, 0.05 at/after 37,500, stable 0.05 through 50,000, evaluation epsilon 0 and no mutation. |
| Checkpoint and snapshots | Distinct versioned resumable and evaluation-only artifacts; immutable atomic publication and checksums; verified completed-episode checkpoint round-trip with online/target/optimizer/replay journal/counters/RNG; reject live-episode, truncated/corrupt/incompatible bundles and retain previous good checkpoint. Exercise mid-episode periodic snapshots and exact 50,000 stop with no synthetic result. |
| Seed pairing and recovery | Retain seed derivation v1.0 known-answer vectors; prove shared arm root seeds but independent trajectories/data, unique attempt IDs excluded from seeds, restored RNG states and unchanged next episode identity after restart, and cumulative wall-time accounting across attempts. |
| Feasibility and resources | Actual M2-generated 1,024-transition replay warm-up and five batch-32 updates; benchmark CPU thread options and accessible backends end-to-end; measure decision/update/checkpoint throughput, candidate/history lengths, RSS and artifact size; establish 50k/8h and campaign/60h projections before official runs. |
| Official training schedule | Exactly three seeds × two arms, 50,000 valid decisions each when complete, six initialization snapshots, snapshots at 10k increments and final, full counters and run manifests; expose failed/incomplete attempts and do not claim equal-budget comparisons for incomplete pairs. |
| Evaluation schedule | Derive exactly 15 policy identities and 100 scenarios/policy (25 seeds × two opponents × two colors), 1,500 total. Frozen epsilon-zero inference makes no gradients or replay writes. Require exact pre/post snapshot stage identity. Hash-chain append-only per-policy attempt journals; fsync scenario starts and completed/incomplete outcomes, record live progress, recover completed rows after interruption, preserve malformed tails without overwriting, and do not double-count resumed scenarios. Preserve raw rows, truncation and terminal distinctions, pairing keys, opponent/color strata and incomplete games. |
| Statistical/reporting controls | Crossed cluster bootstrap over 3 training and 25 evaluation seeds; report per-training-seed outcomes and few-cluster caveat. Pair White/Black by evaluation seed and opponent and bootstrap the 25 evaluation-seed clusters. Preserve a terminal-only analysis that censors cap truncations plus a clearly labeled supplementary capped-reward sensitivity using observed zero reward, never terminal W/D/L. No row-wise independence assumption, selection by test results, favorable-seed exclusion or calibrated Elo. Distinguish simulator from ALE and M4 supervised learning from RL. |
| Scope and operations | Full local Python regression, focused M5/M2/M4 suites, preflight/archive/link checks, clean-clone exact PR HEAD verification, code/config/artifact hashes, memory/storage limits, no prohibited RL libraries, no Stockfish in inference/gameplay/reward, and truthful GitHub CI scope. |

The official evaluation derives from configuration: 25 × 2 × 2 = 100 games per policy and 15 × 100 = 1,500 games. M5-01 through M5-05 remain incomplete until actual implementation, training/evaluation, and evidence satisfy [`ACCEPTANCE_CRITERIA.md`](ACCEPTANCE_CRITERIA.md). The GitHub context/preflight workflow is not the full PyTorch suite.
