# M6-001 — Atari Integration and Evaluation Engineering Report

**Disposition:** engineering implementation and the authorized 35-attempt Stage 3 schedule are complete. **M6-04 is not fully satisfied** because neither frozen M5 policy produced a completed ALE game. This report does not claim PM acceptance, M6 acceptance, G4 approval, or merge.

## Scope and frozen policies

The accepted M5 Double DQN policies were loaded on CPU with frozen weights. The accepted M4 behavior-only model and the `SimpleMaterialHeuristic` and `RandomLegal` baselines were also used. No model was retrained or fine-tuned. Stockfish, optimizer, replay, and training code did not participate in policy decisions. M4 is reported as a supervised-only control; it is not an RL policy.

The M5 snapshots follow the predeclared lowest paired training-seed rule (`20261104`); no Atari result was used to select or replace a checkpoint. The Warm and Scratch checkpoints and sidecars match the accepted M5 root manifest. The M4 checkpoint, sidecar, and root manifest match the accepted M4 record.

The sole Stage 3 configuration was `ALE/VideoChess-v5`, White, raw mode 4, difficulty 0, RGB, frameskip 4, sticky-action probability 0.25. ROM SHA-256 was `d44f2a115393b0a6cbcd5398d62369e652f3670a9ee585883d183e740edad0f7`. The paired M5 seeds were `20261130`–`20261139`, with Warm first for even seeds and Scratch first for odd seeds. Each baseline used seeds `20261130`–`20261134`. The 35-slot schedule and corrected M4 checkpoint digest were frozen before Stage 3 began.

It validates stable ALE RGB, complete verified UCI history, FEN/side/legal candidates, policy identity, and the selected move before execution. History advances only after RGB confirms the player move and Atari reply. Uncertain source/target selection stops safely and does not retry FIRE.

The 26 frame-capped attempts executed exactly 54,000 post-reset action frames (13,500 environment steps × frameskip 4). ## Conclusions and limitations

The M5 policies completed repeated real ALE observation → validation → frozen decision → controller execution → RGB verification loops. This establishes the integration path and move-level reliability under the selected default-v5 configuration. It does **not** establish a completed-game M5 Atari result. No simulator result is presented as an Atari result, and no claim of Atari learning or superiority is made. The 35 attempts are an exploratory integration study, not a statistically decisive tournament or Elo evaluation.
