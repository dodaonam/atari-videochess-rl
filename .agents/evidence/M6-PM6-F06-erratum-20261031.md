## Finding and authoritative scope

The Stage 3 v2 configuration is the authority for the v2 campaign budget. Its frozen `campaign_limits.gameplay_wall_budget_scope` is:

> Stage 3 v2 only; excludes historical v1 and completed M6 diagnostics

## Root cause

At the original Stage 3 v2 source commit `91f51b14690eba12e9e4fd25a4fc1671801fac0d` (tree `4d6ed616971c8f5606a0a7250fe68fa2eea40949`), the shared `_run_manifest()` builder used:

```python
config_data.get("campaign_limits", {}).get("gameplay_wall_budget_includes_diagnostics", True)
```

The frozen v2 config deliberately represented scope with `gameplay_wall_budget_scope` and did not contain the legacy boolean. The generic fallback therefore emitted `true` for v2. The v2 runner then added the correct textual scope but did not replace that nested boolean. The execution record copied the nested value.

## Runtime-impact analysis

The defect affected metadata, not the v2 resource arithmetic or observed experiment. In the frozen source:

- v2 campaigns use a separate `artifacts/.../v2` namespace;
- `run_diagnostics()` rejects v2 runs;
- cumulative v2 wall use is derived from attempt records under that isolated root;
- the 43,200-second wall limit and other ceilings are read from the frozen v2 configuration; the erroneous boolean is not read by the enforcement path.

The immutable raw run manifest records `campaign_wall_seconds_used_before = 0.0` and a 43,200-second cap. The independently rederived v2 gameplay time is 3,519.969 seconds; no campaign resource-stop event occurred. All twenty attempts were within their per-attempt limits; the retained tree is 728,148,524 bytes and maximum recorded process RSS is 620,105,728 bytes. The raw audit found no reset replacement or omitted schedule entry. These checks support the conclusion that the inconsistent boolean did not change execution or results.

## Correction for future manifests

The corrective implementation is in [campaign.py](../../videochess_rl/m6/campaign.py), committed at `8c8eab874054db8e15afa7aa3a0cefb1876fddf2`:

- v2 schema requires the exact frozen v2 textual scope and emits `false` at both the root-level and nested budget metadata fields;
- an explicit contradictory v2 `true` value is rejected;
- v1 schema retains its historical `true` semantics and rejects contradictory scope/boolean combinations;
- unsupported schemas and missing/conflicting scope are rejected rather than inheriting a cross-version default.

No v1/v2 config, schedule, checkpoint, sidecar, ROM, trace, ledger, run manifest, or reported outcome was modified. Runtime budget calculations are unchanged.

Focused regression tests cover v1/v2 serialized metadata, missing/conflicting v2 scope, isolated v2 budget arithmetic, configuration and schedule hashes, and artifact-audit tampering cases. The focused test log is [M6-F06-focused-tests-fbcc982.log](logs/M6-F06-focused-tests-fbcc982.log); final full-suite and preflight evidence are linked from [the corrective closeout report](M6-final-corrective-closeout-20261031.md).
